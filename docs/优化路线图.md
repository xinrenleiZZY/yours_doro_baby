## P0 · 阻断「可交付」，优先补齐

### P0-1 `工程规范` 建立 `.gitignore` ✅ 已完成（2026-10-19）

- **目标**：仓库不再纳入依赖与产物（门禁 G-7）。
- **做法**：新增 `.gitignore`，覆盖 `node_modules/`、`.tmp-smoke-userdata/`、`_smoke-report.txt`、`_shot_*.png`、`_cutout_check.png`、`_strip_*.png`、`_contact_sheet.png` 等。
- **验收标准**：`git status` 不再出现上述路径；清理根目录现存调试产物。

### P0-2 `工程规范+稳定性` 修复并稳定冒烟测试 ✅ 已完成（2026-10-19，26/26 ×3）

- **目标**：门禁 G-2 可信，可重复全绿。
- **做法**：
  1. 修正过时期望值——喂饭/升级/摸头的金币断言改为「相对变化」或注入固定时间，避免受每秒产币干扰；
  2. 消除顺序耦合——用例间重置状态或独立断言；
  3. 消除 rAF 波动——测试用可见窗口运行，或把 `setAction` 的揭示从 `requestAnimationFrame` 改为可等待的确定性路径（仅测试环境注入）；
  4. 把冒烟测试接入 `npm test`（或新增 `npm run test:smoke`）。
- **验收标准**：连续 3 次运行均 17/17 通过；`npm test` 一条命令覆盖单元+冒烟。

### P0-3 `工程规范` 具备打包/发版能力 ⏸ 按用户要求暂缓

- **目标**：能产出一个可安装/可运行产物（门禁 G-5）。
- **做法**：引入 electron-builder（或 Forge），配置 Windows(NSIS)/macOS 目标、图标、`asar`、资源打包规则；新增 `npm run build`。
- **验收标准**：`npm run build` 输出安装包；冷启动进入可交互状态无报错。

## P1 · 规范与稳定性基线

### P1-1 `工程规范` README / LICENSE / CHANGELOG ✅ 已完成

- **目标**：交付三件套齐备，License 合规。
- **做法**：新增 `README.md`（项目简介、玩法、安装与开发、脚本说明）、`LICENSE`（与 `package.json` 的 MIT 对齐）、`CHANGELOG.md`（含 0.1.0 及本轮修复）。
- **验收标准**：三份文件存在且 README 命令可复现。

### P1-2 `工程规范` 引入 Lint / 格式化 / 编辑器配置 ✅ 已完成

- **目标**：风格统一、门禁 G-6。
- **做法**：加入 ESLint(+Prettier 或独立格式化)、`.editorconfig`、`.prettierrc`；统一引号/分号规则（本轮 `app.js` 已被 IDE 保存时格式化，应以此次为准或显式回退并锁定规则）。
- **验收标准**：`npm run lint` 0 error；保存时格式化结果稳定、不再产生整文件改写噪音。

### P1-3 `工程规范` 建立 CI

- **目标**：门禁自动化。
- **做法**：`.github/workflows` 中串起 lint → 单元测试 → 冒烟测试（xvfb/可见窗口）→ `npm audit` → 构建。
- **验收标准**：PR 触发流水线，任一环节失败即阻断合并。

### P1-4 `稳定性与安全` 错误日志与崩溃恢复 ✅ 已完成

- **目标**：线上问题可观测、可定位。
- **做法**：`main.js` 注册 `process.on('uncaughtException'/'unhandledRejection')` 并写日志文件；渲染进程 `window.onerror`/`unhandledrejection` 经 IPC 上报到日志；启动时若检测到上次异常退出则给出提示并保留存档。
- **验收标准**：人为触发异常后，日志文件有记录；存档不丢失。

### P1-5 `稳定性与安全` 加固 IPC 边界 ✅ 已完成

- **目标**：主进程不信任渲染进程入参。
- **做法**：`pet:save` 校验存档结构/类型/大小上限；`win:set-position` 保留现有 clamp 并补类型校验；`pet:actions` 读取失败已有兜底，补齐路径白名单。
- **验收标准**：非法/超大入参被拒绝且不写盘、不崩溃。

### P1-6 `稳定性与安全` 资源构建可复现 ✅ 已完成

- **目标**：`npm run assets` 在不同机器可重复产出。
- **做法**：新增 `requirements.txt` 锁定 Pillow；脚本内用当前解释器/环境变量替代硬编码 `python`；补充失败时的清晰提示。
- **验收标准**：新环境按 README 步骤可一次成功重建 `assets/pet` 与 `actions.json`。

## P2 · 体验、玩法与长期质量

### P2-1 `稳定性与安全` 存档版本迁移 ✅ 已完成

- **目标**：改存档结构时向后兼容。
- **做法**：`hydrate()` 按 `SAVE_VERSION` 做逐版本迁移；新增字段给默认值；迁移逻辑加单元测试。
- **验收标准**：旧版存档可无损升级；迁移用例全绿。

### P2-2 `体验与美术` 音效与无障碍

- **目标**：体验完整度（目标可「美化」上调）。
- **做法**：为喂饭/陪玩/升级/摸头加轻量音效（可开关）；补键盘可达性与必要 ARIA；支持界面缩放适配。
- **验收标准**：关键操作有音效且可关闭；纯键盘可完成喂饭/陪玩/升级。

### P2-3 `体验与美术` 性能与资源体积预算

- **目标**：建立并可回归的性能基线。
- **做法**：测量冷启动、内存、帧率；对 WebP 做有损/尺寸优化（如 `sushi.webp`）；在 CI 记录体积。
- **验收标准**：达到 `总体指南` 第 4.2 节目标值；体积回归有告警。

### P2-4 `体验与美术` 视觉美化升级（可自由调整目标）

- **目标**：整体观感升级，允许「直接美化目标」。
- **做法**：主题化配色、动效节奏打磨、可选皮肤/装扮外观、空状态与过场细节。
- **验收标准**：视觉评审通过；不破坏既有交互与存档（影响面在路线图留痕）。

### P2-5 `玩法与增长` 数值平衡 🟡 已完成第一轮（饿肚子不再停产、衰减放慢），待用模拟校准曲线

- **目标**：经济曲线顺滑、无「卡死/暴富」。
- **做法**：以 `renderer/game.js` 的 `BALANCE` 为参数做模拟，校准产出/成本/升级期望时长与离线收益；产出可复现的平衡表。
- **验收标准**：模拟曲线平滑；关键节点（首升级、离线回归）符合预期区间。

### P2-6 `玩法与增长` 长线系统

- **目标**：提供留存钩子。
- **做法**：成就/图鉴/装扮等其一先行；与现有 `stats` 打通。
- **验收标准**：有新目标可追求，且进度可存档。

### P2-7 `玩法与增长` 指标埋点（可选）

- **目标**：让 4.3 节增长指标可度量。
- **做法**：本地匿名统计次日留存、会话时长、离线触达、升级/装扮转化。
- **验收标准**：指标可采集且默认尊重隐私（本地/可关闭）。

### P2-8 `工程规范` 清理与类型注释 🟡 死代码已清理，JSDoc 仅覆盖关键函数

- **目标**：可维护性。
- **做法**：删除死代码（`main.js` 的 `quitting`、`game.js` 的 `counted` 三元）；为公开函数补 JSDoc；评估 i18n 需求。
- **验收标准**：Lint 无未使用变量告警；`game.js` 导出函数有类型注释。
